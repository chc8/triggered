Response:
You have excellent timing. Those are three critical refinements to make your build pipeline truly professional.

Here is exactly how these changes are handled in the updated script:

1. **Older macOS Support:** I have downgraded the macOS matrix runner to `macos-12` (Monterey) and added the `MACOSX_DEPLOYMENT_TARGET: "12.0"` 
environment variable to the PyInstaller step. This forces Apple's compiler to build a binary that works natively on Intel Macs running Monterey, while 
Rosetta 2 will seamlessly translate it for newer M1/M2/M3 Macs.
2. **Dynamic Version Filenames:** Instead of hardcoding "v1.1.0" into the script, I used GitHub's built-in `${{ github.ref_name }}` variable. When you 
push a tag like `v1.1.0`, GitHub will automatically inject that exact text into your `.zip`, `.tar.gz`, and `.exe` filenames.
3. **Target Script:** `main.py` has been swapped to `triggered.py` across the board.

Here is your final, fully optimized `.github/workflows/build.yml` file. Delete your old workflow code and paste this in:

```yaml
name: Build and Release Pygame

# Triggers when a version tag like "v1.1.0" is pushed, or via manual dispatch
on:
  push:
    tags:
      - 'v*'
  workflow_dispatch:

# Grants the workflow permission to create the Release page
permissions:
  contents: write

jobs:
  build:
    name: Build on ${{ matrix.os }}
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        # ubuntu-20.04 for broader Linux support, macos-12 for older Mac support
        os: [ubuntu-20.04, windows-latest, macos-12]

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.11' 

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install pyinstaller

      - name: Build executable with PyInstaller
        shell: bash
        env:
          # Forces the macOS compiler to target older systems (Monterey)
          MACOSX_DEPLOYMENT_TARGET: "12.0" 
        run: |
          if [ "$RUNNER_OS" == "Windows" ]; then
            pyinstaller --onefile --windowed --add-data "assets;assets" --name Triggered triggered.py
          else
            pyinstaller --onefile --windowed --add-data "assets:assets" --name Triggered triggered.py
          fi

      - name: Package Releases (Preserve Permissions, Rename & Add Version)
        shell: bash
        run: |
          cd dist
          # Dynamically grab the tag you just pushed (e.g., v1.1.0)
          VERSION=${{ github.ref_name }}
          
          if [ "$RUNNER_OS" == "Linux" ]; then
            # Make executable, compress to lock permissions, then delete raw file
            chmod +x Triggered
            tar -czvf Triggered-$VERSION-${{ matrix.os }}.tar.gz Triggered
            rm Triggered 
          elif [ "$RUNNER_OS" == "macOS" ]; then
            # Zip the Mac bundle, then delete raw .app folder
            zip -r Triggered-$VERSION-${{ matrix.os }}.zip Triggered.app
            rm -rf Triggered.app
          elif [ "$RUNNER_OS" == "Windows" ]; then
            # Rename Windows executable for clarity on the Release page
            mv Triggered.exe Triggered-$VERSION-${{ matrix.os }}.exe
          fi

      - name: Upload Artifacts
        uses: actions/upload-artifact@v4
        with:
          # The artifact name itself doesn't need the version, just the files inside
          name: Triggered-${{ matrix.os }}
          path: dist/*

  release:
    name: Create GitHub Release
    needs: build
    runs-on: ubuntu-latest
    # Double-check that this step only runs for tagged releases
    if: startsWith(github.ref, 'refs/tags/')
    steps:
      - name: Download all artifacts
        uses: actions/download-artifact@v4
        with:
          path: artifacts
          merge-multiple: true

      - name: Create Release and Upload Assets
        uses: softprops/action-gh-release@v2
        with:
          files: artifacts/*
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Once you commit this and run your standard `git tag v1.1.0` and `git push origin v1.1.0`, your GitHub Release page will populate with perfectly named, 
cross-platform compatible binaries!
