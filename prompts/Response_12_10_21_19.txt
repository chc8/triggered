Here is exactly why those three things happened, and the final script update to fix them.

### 1. The File Name & The Text Editor Issue

When you upload a raw file directly to a GitHub Release, GitHub strips the Unix file permissions (the metadata that tells Linux "this is an executable program").

Because Linux no longer saw the file as a program, and because it didn't have an extension like `.txt` or `.png`, your Ubuntu desktop environment guessed it was a text file and tried to open it in an editor. This is also why the file was just called `Triggered` instead of `Triggered-ubuntu-24.04`—PyInstaller names the internal file based on the `--name` flag we gave it in the script, ignoring the GitHub artifact name.

**The Fix:** Just like we did for macOS, we need to compress the Linux binary into a `.tar.gz` or `.zip` file *before* uploading it. Compressing it inside the GitHub runner permanently locks in those `+x` executable permissions and allows us to name the download file whatever we want.

### 2. The "Exec format error"

When you ran `chmod +x` to force Linux to run it, you got the `Exec format error`. This almost always means one of two things:

* **File Corruption:** Uploading raw binaries without zipping them can sometimes corrupt the file encoding during the transfer. Zipping the file fixes this.
* **Architecture Mismatch (Most Likely):** GitHub's Ubuntu runners use **x86_64** (Intel/AMD) processors. Are you trying to run this game on a Raspberry Pi, an ARM Chromebook, or a Linux virtual machine on an M1/M2/M3 Mac? If your local machine uses an **ARM** processor, it physically cannot execute an x86_64 binary.
* *Tip:* Open your terminal and type `uname -m`. If it says `x86_64`, the file was just corrupted by the raw upload. If it says `aarch64` or `arm64`, you are on an ARM machine and will need an ARM-specific GitHub runner to build a compatible version.

### The Final Fix: The "Pro" Packaging Step

To solve the naming conventions, preserve Linux permissions, and prevent file corruption, we are going to replace the macOS zipping step with a universal packaging step.

In your `build.yml` file, replace your **Build executable** and **Zip macOS** steps with this block:

```yaml
      - name: Build executable with PyInstaller
        shell: bash
        run: |
          if [ "$RUNNER_OS" == "Windows" ]; then
            pyinstaller --onefile --windowed --add-data "assets;assets" --name Triggered main.py
          else
            pyinstaller --onefile --windowed --add-data "assets:assets" --name Triggered main.py
          fi

      - name: Package Releases (Preserve Permissions & Rename)
        shell: bash
        run: |
          cd dist
          if [ "$RUNNER_OS" == "Linux" ]; then
            # Ensure it is executable, then compress to lock in permissions
            chmod +x Triggered
            tar -czvf Triggered-${{ matrix.os }}.tar.gz Triggered
            rm Triggered # Remove raw file so only the compressed version uploads
          elif [ "$RUNNER_OS" == "macOS" ]; then
            # Zip the Mac bundle
            zip -r Triggered-${{ matrix.os }}.zip Triggered.app
            rm -rf Triggered.app
          elif [ "$RUNNER_OS" == "Windows" ]; then
            # Windows doesn't lose permissions, but let's rename it for the release page
            mv Triggered.exe Triggered-${{ matrix.os }}.exe
          fi

```

### What this does:

1. PyInstaller builds the raw game named `Triggered`.
2. **On Linux:** It packages it into a nice `Triggered-ubuntu-24.04.tar.gz` file. When you download and extract this, it will be a fully functional, double-clickable executable.
3. **On Mac:** It creates `Triggered-macos-latest.zip`.
4. **On Windows:** It renames the executable to `Triggered-windows-latest.exe`.

```yaml
name: Build and Release Pygame

on:
  push:
    tags:
      - 'v*'
  workflow_dispatch:

# Grants the workflow permission to create the Release page
permissions:
  contents: write

jobs:
  build:
    name: Build on ${{ matrix.os }}
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        # ubuntu-20.04 is used for maximum backward compatibility on Linux
        os: [ubuntu-20.04, windows-latest, macos-latest]

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.11' # Change to your preferred Python version

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install pyinstaller

      - name: Build executable with PyInstaller
        shell: bash
        # NOTE: If you don't have an "assets" folder, remove the --add-data flags below!
        run: |
          if [ "$RUNNER_OS" == "Windows" ]; then
            pyinstaller --onefile --windowed --add-data "assets;assets" --name Triggered main.py
          else
            pyinstaller --onefile --windowed --add-data "assets:assets" --name Triggered main.py
          fi

      - name: Package Releases (Preserve Permissions & Rename)
        shell: bash
        run: |
          cd dist
          if [ "$RUNNER_OS" == "Linux" ]; then

            chmod +x Triggered
            tar -czvf Triggered-${{ matrix.os }}.tar.gz Triggered

            # Zip the Mac bundle, then delete raw .app folder
            zip -r Triggered-${{ matrix.os }}.zip Triggered.app
            rm -rf Triggered.app
          elif [ "$RUNNER_OS" == "Windows" ]; then
            # Rename Windows executable for clarity on the Release page
            mv Triggered.exe Triggered-${{ matrix.os }}.exe
          fi

      - name: Upload Artifacts
        uses: actions/upload-artifact@v4
        with:
          name: Triggered-${{ matrix.os }}

    name: Create GitHub Release

    runs-on: ubuntu-latest

    if: startsWith(github.ref, 'refs/tags/')
    steps:
      - name: Download all artifacts
        uses: actions/download-artifact@v4
        with:
          path: artifacts
          merge-multiple: true

      - name: Create Release and Upload Assets

        with:
          files: artifacts/*
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

```
